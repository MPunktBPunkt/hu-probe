# WiFi vs OTG — Lab 0.2.14 / 0.2.15 (Abend)

**ESP:** Lab `.88` · **Auto:** `.89` (kurz OTA **0.2.14**, danach Strom weg)  
**Bins:** `firmware/dist/hu-probe.0.2.14.esp32s3.bin` · `…0.2.15…`

## Stimulus-Epistemik (wichtig)

| Stimulus | Modelliert | Rolle |
|----------|------------|--------|
| Dauer-`dd` | **Worst-Case Sonde**, nicht NBT | Repro WiFi-Death / Overflow |
| Burst-`dd` (z. B. 2–5 s an, 10–30 s Pause) | eher HU-Playback-Pace | realistischer Coex-Test |
| BMW-S0 Feld | Golden (4 KiB, Gap ~3,6 ms, Fenster) | eigentliche Timeline |

**Fehlannahme verworfen:** „Lab muss WiFi unter Dauer-`dd` halten, sonst keine HU-Messung.“  
HU liest in **Bursts/Fenstern**, nicht endlos. Capture läuft oft weiter, während WiFi tot ist — für unbroken Timeline zählt Burst/Playback, nicht Dauerloop.

## Symptom (FACT) — unter Lab-Dauerstress / OTG

| Zustand | LED | HTTP |
|---------|-----|------|
| OTG ab | blau (Idle) | stabil |
| OTG an, Host liest kurz | grün | kurz ok |
| unter Dauer-`dd` / anhaltender Last | **gelb blink** | tot (`WiFi.status() != CONNECTED`) |
| Supervision | Auto-`ESP.restart()` / Soft-Detach-Versuch | Recovery oft ~35–40 s; manchmal RST-Loop |

Gelb = **Assoc weg**, nicht nur Collector-TCP (Orange wäre TCP-only).

## Messungen Lab

| FW | Trigger | HTTP down | Recovery | Notes |
|----|---------|-----------|----------|-------|
| 0.2.13 | sustained `dd` | ~2,5 s | ~73 s | Baseline |
| 0.2.14 | OTG + Host-Reads | ~3 s | ~36 s | Drain/TCP-Yield; Stall-Reconnect entschärft |
| 0.2.15 | OTG einstecken | ~7 s (nach Reads↑) | ~36 s + RST | `PS_NONE` + TX 19.5 + Hub unter USB gedrosselt — **reicht nicht** |

MSC/`reads` laufen weiter, während WiFi tot ist. Ohne OTG: sofort wieder HTTP.

## Was 0.2.14 / 0.2.15 ändern

**0.2.14**

- `ProbeClock::publishUs` auch in Session start/stop/marker + Status/Health  
- TCP-Flush 48 + yield; BOT-Drain kleiner + yield  
- TCP-Stall: nur loggen (kein Assoc-Bounce — hatte Lab verdreht)

**0.2.15**

- `esp_wifi_set_ps(WIFI_PS_NONE)`, `WiFi.setTxPower(19.5)`, `setAutoReconnect`  
- Hub-Heartbeat unter `msc.plugged()` nur ~60 s  
- Status/Health-Cadence unter USB verdoppelt; Drain 16

## Konsequenz für GATE-01 / Morgen

- Instrument-Timeline kann unter HU-Reads **reißen** (Gelb/RST); Events im Ring ggf. nach Recovery nachziehbar.  
- „Lange unbroken BMW-S0-Timeline“ **blockiert**, bis Coexistenz gelöst.  
- Lab-Kill 1–3 / Triple 0.2.13 bleiben gültig (ohne Dauer-`dd`/mit Recovery).

## Lab-Workaround 0.2.16 / 0.2.17 — Soft-Detach-Coex

**Idee:** Physikalisch OTG drin; bei WiFi-Verlust **D+ soft-detach** → Assoc/TCP erholen → Ring flushen (~8 s) → soft-attach.

| | |
|--|--|
| 0.2.16 | Soft-Detach in `loop` — **FAIL unter Dauer-USB**: Loop verhungert, LED permanent gelb, Stick bleibt `soft_attached` |
| 0.2.17 | dieselbe Logik in **FreeRTOS-Task prio 25** (über `usbd` 24) — Bin gebaut, OTA braucht einmal stabiles HTTP (OTG kurz raus) |
| Geeignet | Lab unattended / Absicherung |
| Nicht | BMW-Autoplay als Dauer-Duty-Cycle |
| Nächster Lab-Schritt | **Burst-Muster** statt Dauer-`dd` auf demselben FW-Stand |

Desk-Coex (Power/Starve/RF) bleibt offen.

## Nächster Fix-Kandidat (echt)

USB↔WiFi auf IDF/Coex-Ebene (Task-Prio, SOF-Last, Phy) — Method `usb-wifi-coex-discrimination`.
